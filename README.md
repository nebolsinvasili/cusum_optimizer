# CUSUM ARL Calculator

Инструмент для расчёта Average Run Length (ARL) двусторонних CUSUM-контрольных карт на знаковой статистике (**SN**) и знаково-ранговой статистике (**SR**), а также подбора параметров `(k, H)`, при которых ARL достигает целевого значения (по умолчанию 370). Предназначен для инженеров по качеству и аналитиков, настраивающих контрольные карты CUSUM на требуемые свойства.

## Возможности

- Вычисляет ARL методом Монте-Карло для сетки параметров `k × H` (по умолчанию 41×41 = 1681 комбинаций)
- Поддерживает два типа карт через флаг `--chart SN|SR`: знаковую (SN) и знаково-ранговую (SR)
- Ищет пару `(k, H)`, дающую ARL, ближайший к целевому значению
- Параллелит вычисления по всем ядрам CPU (OpenMP)
- Возобновляет прерванный расчёт с контрольной точки
- Сохраняет результаты в CSV и выводит топ-N лучших пар
- Настраивается через JSON-конфиг или аргументы командной строки

## Описание проекта

CUSUM-карта отслеживает накопленные отклонения процесса от целевого уровня и сигнализирует при выходе за порог. Проект реализует **двустороннюю** CUSUM-карту; на каждой итерации берётся выборка размера `n` из стандартного нормального распределения и строится статистика подгруппы, после чего обновляются два кумулятивных счётчика `C⁺` и `C⁻` с параметром сдвига `k`:

```
C⁺ = max(0, C⁺ + stat − k)
C⁻ = max(0, C⁻ − stat − k)
```

Статистика подгруппы зависит от типа карты (`--chart`):

- **SN (знаковая)**: `stat = 2·t − n`, где `t` — число неотрицательных наблюдений. Учитывает только знаки наблюдений, диапазон `±n`.
- **SR (знаково-ранговая)**: `stat = Σ sgn(xᵢ)·rank(|xᵢ|)`, ранги — по абсолютному значению (средний ранг при связях). Учитывает знаки и величины наблюдений, диапазон `±n(n+1)/2`.

Сигнал происходит, когда `C⁺ ≥ H` или `C⁻ ≥ H`. Итоговый результат по каждой паре `(k, H)` — средняя длина серии до сигнала (ARL). Программа перебирает сетку значений `k` и `H`, запускает прогоны Монте-Карло и выбирает пару, чей ARL ближе всего к целевому (`target_ARL`).

## Настройка

Основные параметры задаются в `config/default_config.json`:

| Поле | Описание | Значение по умолчанию |
|------|----------|-----------------------|
| `simulations` | Число прогонов Монте-Карло на пару `(k, H)` | `5000` |
| `n` | Размер подгруппы (число наблюдений на итерацию) | `14` |
| `max_iter` | Максимальная длина серии (обрыв, если сигнала нет) | `5000` |
| `target_ARL` | Целевой ARL | `370.0` |
| `n_cores` | Число ядер (0 или ≤0 = автоопределение) | `0` |
| `tolerance` | Ранняя остановка при отклонении ≤ tolerance (−1 = отключено) | `-1.0` |
| `top_n` | Сколько лучших пар выводить | `10` |
| `chart_type` | Тип карты: `SN` (знаковая) или `SR` (знаково-ранговая) | `SN` |
| `k_values`, `H_values` | Сетка параметров | `3.0 … 7.0`, шаг 0.1 |
| `resume` | Продолжить прерванный расчёт | `false` |

Полное описание схемы конфига и форматов файлов — в [docs/API.md](docs/API.md).

Программа выводит конфигурацию, прогресс-бар и таблицу топ-10 пар `(k, H)` с минимальным отклонением ARL от целевого. Файлы результатов создаются в текущей директории:

- `best_arl_pairs.csv` — топ-10 пар с отклонением от целевого ARL
- `arl_calculation.log` — журнал запусков

### Запуск знаково-ранговой карты (SR)

```bash
./bin/cusum --chart SR --simulations 1000 --k_start 1 3 0.5 --H_start 40 120 10
```

> **Важно**: статистика SR имеет масштаб `±n(n+1)/2` (для `n=14` это ±105), поэтому сетка по умолчанию `[3.0, 7.0]` (рассчитана на SN) для SR непригодна — задавайте диапазоны `k` и `H` явно через `--k_start`/`--H_start` или конфиг. Если сетка не задана явно, программа выводит в stderr предупреждение.

### Быстрый запуск (уменьшенная сетка)

```bash
./bin/cusum --simulations 1000 --k_start 5.0 6.0 0.5 --H_start 4.0 5.0 0.5
```

## Валидация (`make validate`)

Тест `tests/validate` проверяет симулятор по книге Qiu, *Introduction to
Statistical Process Control*, гл. 4.2.2 (знаковая CUSUM-SN и знаково-ранговая
CUSUM-SR карты):

1. **Точное распределение статистики** — для SN: `s = 2t - n` (~`Bin(n, 1/2)`);
   для SR: распределение Уилкоксона для знаковых рангов, `s = 2T_n^+ - n(n+1)/2`.
2. **Точный ARL марковской цепью** (метод книги, §4.2.2.4.3): по теоретическому
   распределению строится цепь Маркова счётчиков `C± = max(0, C± ± s - k)`,
   сигнал при `C± ≥ h`. Эталон — связанная цепь по парам состояний `(C⁺, C⁻)`
   с поглощением при `C⁺ ≥ h` **или** `C⁻ ≥ h` (рекурсии 4.10–4.11),
   сопрягаемая Гауссом–Жорданом.
3. **Сверка Монте-Карло**: `Simulator` должен воспроизводить точный ARL с
   допуском ±5% на контрольных точках (SN n=10: k=6,h=4 → 465.0 и k=5,h=4 →
   260.8; SR n=10: k=34,h=20 → 388.6 и k=38,h=16 → 451.1) — при
   `--simulations 10000` по умолчанию (см. `make validate`), задаётся флагом
   `--simulations N`. Расхождение MC↔точное после многопоточности — в пределах
   долей процента (ГПСЧ у каждого потока свой, без гонок).

Книжные дизайны с номинальным ARL_IC=500 (рис. 4.5/4.6):

- SN (n=10, k=6, h=4): точный ARL ≈ 465 — проверяется в допуске 15% от номинала;
- SR (n=10, k=41, h=24): собственная программа книги (приложение B) при
  `h > M - k = 14` печатает «Not possible» и фактически оперирует эффективной
  границей `h_eff = min(h, M - k) = 14`; точный ARL при ней ≈ **486.9**, что
  сходится с номиналом рис. 4.6 (~500, отклонение 2.6%, допуск 10%). Проверяется
  и MC(k=41, h_eff=14) против точного значения (±5%). Буквальное же h=24 даёт
  80613.3 — вырождение (h за пределом достижимых состояний статистики SR),
  печатается как INFO. Примечание: перцентили рис. 4.6 (Q1=78, Med=228, P95=1905)
  отличаются от цепи прил. B (Q1=140, Med=338, P95=1457) — по среднему источник
  согласуется, по форме — внутренняя несогласованность данных рисунка.

Возвращает ненулевой код при любом провале (в отличие от основного бинарника,
который всегда завершается с кодом 0).

## Python-биндинги (библиотека)

Проект предоставляет Python-пакет `cusum`, использующий ctypes для вызова C++ ядра. Пакет можно использовать локально в проекте или устанавливать как библиотеку в других проектах.

### Установка Python-пакета

**Linux / macOS:**

```bash
# 1. Собрать shared library
make lib

# 2. Установить Python-пакет (режим разработки — симлинк, изменения в коде видны сразу)
pip install -e .

# Или скопировать .so в системную директорию и установить глобально:
cp lib/libcusum.so /usr/local/lib/
pip install .
```

**Windows (MSYS2 / MinGW):**

```bash
# 1. Собрать shared library (в MSYS2 mingw64 терминале)
make lib

# 2. Установить Python-пакет
pip install -e .
```

При сборке через MinGW shared library будет `lib/libcusum.dll` (или `libcusum.dll.a` + `cusum-0.dll`). Python автоматически найдёт её через `ctypes.CDLL`.

**Windows (Visual Studio / MSVC):**

Для MSVC-инструментария потребуется CMake или ручная сборка DLL:

```powershell
# Пример через MSVC cl.exe (упрощённый)
cl /std:c++17 /EHsc /O2 /MD /LD /I include /I "C:/path/to/nlohmann" ^
    src/Calculator.cpp src/Config.cpp src/Simulator.cpp src/Utils.cpp ^
    src/ProgressBar.cpp src/bridge.cpp /Fe:libcusum.dll /link /IMPLIB:libcusum.lib

# Установить переменную окружения для Python
set CUSUM_LIB_PATH=%CD%\libcusum.dll
pip install -e .
```

> **Важно для Windows:** shared library (`.dll`) должна быть доступна Python при импорте. Если `pip install -e .` не находит DLL автоматически — установите переменную окружения `CUSUM_LIB_PATH` на полный путь к `libcusum.dll`.

### Использование в Python

```python
from cusum import Cusum, Config, Result, Distribution

# --- Конфигурация ---
config = Config(
    simulations=5000,       # число прогонов Монте-Карло
    n=14,                   # размер подгруппы
    max_iter=5000,          # макс. длина серии
    target_ARL=370.0,       # целевой ARL
    n_cores=0,              # 0 = автоопределение ядер
    chart_type="SN",        # "SN" или "SR"
    k_range=(3.0, 7.0, 0.1),  # (начало, конец, шаг)
    H_range=(3.0, 7.0, 0.1),
    top_n=10,
    tolerance=-1.0,         # -1 = ранняя остановка отключена
)

cusum = Cusum(config)
```

**Расчёт ARL для одной пары (k, H):**

```python
arl = cusum.calculate_arl(k=5.5, H=4.5)
print(f"ARL = {arl:.2f}")  # например, ARL = 368.42
```

**Расчёт ARL с полной статистикой распределения:**

```python
dist = cusum.calculate_arl_distribution(k=5.5, H=4.5)
print(f"ARL={dist.ARL:.2f}, mean={dist.mean:.2f}, stddev={dist.stddev:.2f}")
print(f"Перцентили: p5={dist.p5:.0f}, p25={dist.p25:.0f}, p50={dist.p50:.0f}, "
      f"p75={dist.p75:.0f}, p95={dist.p95:.0f}")
print(f"Диапазон: [{dist.min:.0f}, {dist.max:.0f}]")
```

**Полный перебор сетки (k, H):**

```python
results = cusum.run()  # возвращает List[Result]
print(f"Рассчитано {len(results)} пар")

for r in results[:5]:
    print(f"  k={r.k:.3f}, H={r.H:.3f}, ARL={r.ARL:.2f}, dev={r.deviation:.2f}")
```

**Лучшая пара (ближайшая к target_ARL):**

```python
best = cusum.best_pair()
print(f"Лучшая пара: k={best.k:.3f}, H={best.H:.3f}, ARL={best.ARL:.2f}")
```

**Загрузка конфига из JSON:**

```python
cusum = Cusum()
cusum.load_json('{"simulations": 1000, "n": 14, "chart_type": "SR"}')
```

### Тип карты SN vs SR

```python
# SN — знаковая статистика (по умолчанию)
arl_sn = cusum.calculate_arl(5.5, 4.5, chart_type="SN")

# SR — знаково-ранговая статистика
# Важно: для SR сетка k/H должна покрывать диапазон ±n(n+1)/2
config_sr = Config(
    simulations=1000,
    n=14,
    chart_type="SR",
    k_range=(1.0, 3.0, 0.5),
    H_range=(40.0, 120.0, 10.0),
)
cusum_sr = Cusum(config_sr)
arl_sr = cusum_sr.calculate_arl(2.0, 80.0, chart_type="SR")
```

### Пример: подбор k, H для заданного ARL

```python
from cusum import Cusum, Config

# Быстрый поиск (мало прогонов, грубая сетка)
config = Config(
    simulations=1000,
    n=14,
    target_ARL=370.0,
    k_range=(4.0, 6.0, 0.25),
    H_range=(3.0, 6.0, 0.25),
)
cusum = Cusum(config)
best = cusum.best_pair()
print(f"Приближение: k={best.k:.3f}, H={best.H:.3f}, ARL={best.ARL:.2f}")

# Уточнение (узкая сетка вокруг найденного)
config2 = Config(
    simulations=5000,
    n=14,
    target_ARL=370.0,
    k_range=(best.k - 0.1, best.k + 0.1, 0.01),
    H_range=(best.H - 0.1, best.H + 0.1, 0.01),
)
cusum2 = Cusum(config2)
best2 = cusum2.best_pair()
print(f"Уточнение: k={best2.k:.3f}, H={best2.H:.3f}, ARL={best2.ARL:.2f}")
```

## Roadmap

Планируемые направления (на основе текущих пробелов в проекте — список предложений):

- **Выходные коды**: сейчас программа всегда завершается с кодом 0; ввести ненулевые коды при ошибках (не найден конфиг, не открывается файл)
- **Распределение длин серий**: функции `simulateBatchWithDistribution` уже есть в коде, но не подключены к CLI — добавить режим вывода полной статистики (процентили 5/25/50/75/95, stddev, минимум/максимум)
- **Утилизация** `ResultManager`: класс реализован, но не участвует в сборке (Makefile его не компилирует) — либо использовать, либо удалить
- **Визуализация**: скрипты построения контурных графиков ARL по сетке `(k, H)`
- **Разные целевые ARL**: поддержка нескольких целей за один запуск

Готово (реализовано):

- **Python-биндинги**: ctypes-обёртка для вызова из Python, pip-установка, Windows-совместимость
